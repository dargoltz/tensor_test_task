### Проект реализован в минимальном стеке:

- typer для CLI
- psycopg для работы с БД
- python-dotenv для работы .env файлами

### Переменные окружения:
Для тестового запуска в репо лежит уже заполненый .env файл

- DB_URL
- DEFAULT_DATA_PATH - путь к файлу для импорта (по умолчанию в проекте размещен в ./db/seeds/input_data.json)

### Сборка:

- Поднять postgres из docker-compose.yml
- uv sync для сборки .venv

### Запуск:

- etrypoint в main.py - запускать любым удобным способом

Пример с uv:

`uv run python -m tensor_test_task.main --help` - справка по CLI

`uv run python -m tensor_test_task.main import-data` - импортировать данные

`uv run python -m tensor_test_task.main get-employees 3` - получить сотрудников из офиса сотрудника с ID 3

### Основные команды:

- `import [PATH]` - импортирует записи из JSON файла и сохраняет их в БД
- `get_employees [EMLOYEE_ID]` - выводит информацию о всех сотрудниках в организации, к которой прикреплен указанный
  сотрудник

### Ограничения:

- по умолчанию размер JSON файла не должен превышать 10Мб

### Логика работы

- import метод парсит JSON по указанному пути, формируя values для batch insert запроса в бд
- get_employees метод выполнят запрос с двумя рекурсивными CTE для поиска организации, к которой прикреплен сотрудник,
  и для поиска всех сотрудников найденной организации

### Оценка сложности выборки:

- O(N) для подъема вверх (от сотрудника до организации) - быстро при малой глубине иерархии
- O(N) для обхода в глубину (от организации до сотрудников) - медленнее тк иерархия может состоять из большого кол-ва
  узлов
